# Night-shift sandbox tool session (Commit 03 contract)

This is an **offline host-side protocol contract**, not an enabled Hyper-V adapter. The old `WorkerChannel`/`HyperVSerialTransport` version-1 whole-task JSONL protocol and guest inference prototype remain intact. No guest tool service, pipe adapter, workspace transfer, or live inference has been enabled; Gates A/B are still blocked. See [plan](night_shift_plan.md) and [status](night_shift_status.md).

`SandboxToolSession` is created only by trusted orchestration for a persisted Hyper-V sandbox record, a job, an approved worker profile and tool schemas, a freshly generated 128-bit session nonce, and a monotonic deadline. Only `session.model_tools()` is passed to a model executor: it implements `WorkerToolProvider` and exposes no workspace loading or export methods. The orchestrator owns `start()`, `load_chunk()`, `finalize()`, `export_chunk()`, `cancel()` and `close()`. The host independently checks profile tool names, JSON argument size and the existing command policy before sending a model tool call. The guest will also independently validate arguments and enforce workspace/OS policy; protocol validation alone cannot make a guest safe.

## Wire contract

A future Hyper-V COM1 adapter must implement `ToolSessionTransport.send(frame, timeout_seconds)`, `receive(max_bytes, timeout_seconds)` and `close()`. `receive` returns **one complete** newline-terminated UTF-8 JSON object, with no trailing/extra frames; it must reject/avoid unbounded buffering. Both I/O methods must enforce the passed timeout, and `close` must unblock a concurrent I/O call. Adapt the existing reviewed named-pipe/framing code rather than sharing the existing whole-task channel state machine. A daemon reader thread without interruptible I/O is **not** an implementation of this transport.

All messages use `version: 1`, `type`, `job_id`, `sandbox_id`, `session_id` and a bounded JSONL frame (64 KiB default, at most 1 MiB). Host sends `hello`, expects exactly `hello_ack` with the same binding; an echoed nonce guards against accidental wrong-session/replayed replies, **not** against a compromised guest. After the handshake, host sends one `request` with monotonically increasing `request_id`, an operation and a payload; guest sends one matching `response` with `ok: true` and a payload, or `ok: false` and a typed `{code, message}` error. Unknown version/type/fields, malformed/truncated/oversized frames, wrong identity or request ID, and unsupported error codes terminate the session. No unsolicited guest request can cause host tool execution.

Operations are phase-bound: `load_chunk` (loading), `tool` (ready), `finalize` (ready -> exporting), `export_chunk` (exporting). `load_chunk` and `export_chunk` use bounded base64 chunks and monotonic offsets, with a 4 MiB per-direction initial cap; detailed archive/manifest validation and actual implementation belong to Commit 04. `finalize` stops all further model tools. Initial protocol permits only one outstanding operation; concurrent calls fail rather than queue. Transport/remote errors close the session. A timeout or disconnection during *any* mutating request means its completion is unknown: do **not** replay it automatically. A concurrent cancellation marks the session closed and closes transport so even a late success cannot become a worker result; guest termination/cleanup still belongs to orchestrator lifecycle policy. A send/response pair is bounded by a 30-second operation deadline by default and the remaining job deadline; each transport I/O must also honor its supplied remaining timeout. This is not a claim that synchronous guest work is interruptible without a real adapter.

The fake-transport tests are contract evidence only. The eventual guest must prove per-session ownership of the assigned workspace, never accept host-tool or network requests, and reject stale/duplicate request IDs. The named-pipe ACL/creator identity and VM/session binding must be reviewed on an authorized host before Gate B. No real-host run or image changes in this commit.
