# Commit 08: bounded review evidence and persistence

**Offline host-side foundation; not a live job backend.** Gates A/B remain blocked. `night_shifts.review_patch` compares the *entire* approved base snapshot with a complete, bounded final file enumeration; the model does not select which files go into the patch. New/deleted/modified and mode-only changes have hashes and an explicit Git-style text patch. No-op coding work is not ready for review. Non-UTF-8/binary, LFS, links, submodules, oversized or otherwise unsupported content must fail closed; a missing guest export is **not** an empty workspace. File/directory swaps and empty-file creation/deletion are refused until replay handling supports them. Final bytes are untrusted even if they came over an authenticated, job-bound host pipe.

`ReviewBundleStore.collect` takes the frozen job policy, task, approved base, optional **complete** final files, host-recorded command/check observations, worker outcome/usage, an execution-VM cleanup status, and an optional **host-supplied** replay receipt. It is called by the orchestrator, never by the model. Worker-supplied checks and artifacts do not create check evidence. Observed check output is still guest-originated and not independently attested by a compromised guest; the host records which operation it requested and what it received. Command outputs are bounded and have explicit timeout/truncation flags; JSON-escaped report bytes are not automatically rendered to a terminal. A consumer must keep that escaping or otherwise neutralize control characters. Strict USD jobs remain blocked by execution policy, not certified by the review report.

Each approved job ID gets one write-once trusted directory with an `incomplete.json` marker created before evidence is built. `report.json` and, when possible, `patch.diff` are bounded and hashed by `manifest.json`; `complete.json` is written last and references the manifest digest. `complete.json` means **bundle bytes were saved**, not that checks passed or the task succeeded. A crash or storage failure before the last marker leaves an incomplete bundle on restart; `read()` refuses missing, unsafe or tampered evidence. No automatic retry or overwrite of an ambiguous partially written bundle. Keep trusted storage under an administrator-owned ACL on Windows; POSIX chmod alone does not supply Windows ACL confinement. The old `ArtifactCollector` remains the optional path for bounded worker-authored text artifacts; this store holds mandatory host-generated review evidence, not a second guest artifact transfer mechanism.

The report separates execution outcome, host-observed checks, human review (`not_reviewed`), VM cleanup, limitations and missing evidence. A coding submission needs nonempty changes, configured passing checks, clean observed cleanup, and a matching replay receipt from a **different** clean disposable sandbox before `ready_for_review`. Fake receipts in unit tests exercise shape/binding only. The code does not yet obtain final-workspace bytes from the real guest, run trusted checks in Hyper-V, validate patch round-trip in a real second VM, verify pipe identity/ACLs, or perform orchestration cleanup. The approved backend must supply those operations before any live task or actual readiness claim. Test-owned `git apply` on a temporary fixture is an offline patch-syntax check only; never apply/replay patches in the user's checkout or execute repository-controlled code on the host.

Review after Gate B: implement the bounded guest final-file export with complete enumeration, identity/digest binding and failure cleanup; call the collector even when the guest crashes; request configured checks separately from model calls; replay the patch in another disposable VM and compare full final-file hashes; destroy both VMs even if storage/event reporting fails. If bundle persistence fails, keep the interrupted marker, report unresolved cleanup independently and refuse to label the job clean. Document fixture policy explicitly before broadening binary/empty-file support.
