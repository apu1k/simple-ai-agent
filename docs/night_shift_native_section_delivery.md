## Fixed composition and the actual stop point

The intended same-assembly route is:

```text
prerequisite independently trusted pre-load/installed-policy/starter route
  -> existing approval policy acquisition and permanent claim
  -> canonical request decoding / independent byte pins / metadata equality
  -> immutable outer-request staging (NO native work)
  -> acquire and retain exact executable/configuration/scratch targets
  -> private non-inheritable two-process kill-on-close job
  -> held-target pre-create verification
  -> bind THIS process core's clock and actual stopAt (NO native work)
  -> publish / verify / remove all owned write capability
  -> freeze conservative common-QPC limit and bounded metadata command
  -> suspended worker creation with explicit ONE-handle list AND atomic JOB_LIST
  -> membership / held-target pre-resume verification / original-window check
  -> resume and existing exact-job observation/stop/close sequence
  -> conditional target release and existing conditional approval release
```

`GuardianRequest` clones the bounded complete outer bytes and verifies their
length/SHA-256 again against the independent pin and derived immutable plan. It
has no codec, file/token observation, authorization or carried application import.
Returned copies cannot mutate its snapshot. A mutation between initial decoding
and this second pin check cannot silently substitute another request.

Both staging calls are internal compile-time operations, not public callbacks
or caller-selected code. They must not create/resume a process or perform native
publication. Existing kernels which do not implement the optional interface keep
exactly their old execution path, including no extra clock reads from the new
conditional hooks. No default selects the new adapter.

Crucially, request admission does NOT guess the eventual worker deadline. The
actual process core binds its `stopAt`, after the held pre-create gate, from the
SAME clock and already shortened deadline that it will enforce itself. A UTC
change or other earlier cap applied during held-guardian construction cannot
leave the delivered cap later than the parent's real execution stop point.
The existing five-second outer stop reserve is NOT delivered as worker execution
time. Worker-side stop time remains INSIDE the delivered earlier window, not
added back; insufficient nested windows refuse.

The new section window retains a rollback/nonfinite guard around that already
guarded same-origin clock. Every native phase, readback and publication boundary
consumes the same cap; setup is never granted a fresh duration. QPC capture uses
the EARLIER common counter, a later local sample, stable frequency and bounded
ordered samples. It floors conversion, subtracts a millisecond plus rounding
margin, rejects overflow/expired/oversized intervals and freezes the absolute
common-machine limit before process construction. The existing worker receiver
maps it conservatively into its own clock; foreign process-relative Stopwatch
values are never serialized as local timestamps.

This carries the EXISTING guardian window to the worker. It does NOT establish
trusted original-deadline delivery from a pre-load starter INTO the guardian,
bound module loading, or interrupt arbitrary blocking native/CLR work. Those
remain obligations of the missing protected starter and independent watchdog.
Native counter coherence/rates and Windows command parsing remain unverified.

## Section rights, publication and ownership

The native producer creates ONLY an unnamed, private BA/SYSTEM-protected,
non-inheritable pagefile-backed `PAGE_READWRITE` section with the exact logical
request length, at most 32 KiB. There is no caller-selected name/path/file,
executable mapping, directory creation, input reopen, named pipe, stdin parser,
ACL repair, reset or retry.

The managed publisher is terminal and checks every owned resource for null/alias
before adoption. It:

1. Verifies the initial full section capability and non-inheritance flags.
2. Maps a bounded write view, copies only the pinned snapshot and hashes complete
   readback. Partial/corrupt/short data cannot become publication success.
3. Unmaps the writable view, then duplicates ONLY `SECTION_MAP_READ` with the
   inheritance flag set and `DUPLICATE_SAME_ACCESS` disabled.
4. Requires the duplicate's exact read-only rights and inheritance flags, then
   closes/disarms the original full-access section handle.
5. Reads/hashes through a fresh read-only view after removal of all OWNED write
   capability, with checked unmap and original-window checks.
6. Transfers only the read capability to a private parent lease. Immediately
   before creation, reverify the same read capability, bytes and window again.

No other write aliases or concurrent uncontrolled spawns may exist in the trusted
dedicated parent. The fixed code creates none; arbitrary Administrator/SYSTEM
handle duplication or trusted-host tampering cannot be disproved by local rights
checks. Such actors, the OS/CLR and reviewed load closure remain trusted. The
section descriptor, `NtQueryObject` access/layout and actual alias/inheritance
semantics still need native characterization; source and fake models are not
proof of those Windows properties.

Parent read-capability cleanup is deliberately distinct from import/target
locking. After successful inheritance the child has its OWN kernel reference;
closing the parent's read handle does not revoke that reference and does not
release executable targets or verified imports. Thus bounded local section/
attribute/environment/security scratch may be closed in `finally`, including
on uncertain creation. This does NOT permit unconditional disposal of the held
launch/import leases. Their existing exact-owned child-absence rules remain in
force. Each local native release is disarmed before a single attempt; cleanup
failure is UNKNOWN, not proof of closure or permission for a retry.

## Exact inherited capability and fixed worker command

The adapter stages request/window once, requires the fixed guardian host and
exact enabled operator through the existing native host gate, and owns one exact
private two-process job. New job/creation attempts are terminal. Publishing or
process creation without the staged request, bound real window, matching plan,
host role and exact job refuses. These consistency gates are NOT authentication.

The process attribute list has exactly two entries:

- `PROC_THREAD_ATTRIBUTE_JOB_LIST`: the single exact-owned job, assigned AT
  suspended process creation, never create-then-assign or breakaway.
- `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`: ONLY the exact inheritable read-only
  section handle. No job/process/thread/standard handles or arbitrary additional
  capability is included.

`bInheritHandles=true` is used ONLY with that required explicit one-handle list
AND atomic job attribute. Unsupported setup refuses without a fallback, retry,
PID lookup or broad termination. Process/thread descriptors remain private and
non-inheritable. There is no generic inheritance toggle or list supplied by a
request. The historical guardian and Python adapters still disable inheritance.

The application is always the held `validator-provision-worker.exe`. The command
is strictly below 1,024 UTF-16 characters and carries only the existing versioned
mode, canonical decimal handle, independent request count/hash, original budget/
expiry and QPC limit/frequency. The potentially 32 KiB outer request is NOT
Base64-expanded into argv or reduced to a worker projection. These metadata are
non-secret consistency fields, not credentials/tokens or an authorization grant.
SystemRoot/WINDIR/PATH use the existing fixed native system-directory helper;
CWD is the held launch root and TEMP/TMP the held private scratch. No parent
provider environment, shell, caller-selected module/command or inherited stream
is accepted.

Native creation validates returned handles before transfer. Attribute/environment/
section/security cleanup precedes child-handle transfer. A failure closes local
child handles once while the core still owns the kill-on-close job. Since the
core marks creation attempted BEFORE entering the adapter, even a publisher
failure inside that call conservatively retains targets after uncertainty.
The existing process core handles whole-job stop/observation; no nonzero exit,
timeout or cleanup result becomes provisioning acceptance. Protected receipts
and independent reconciliation remain required.
