# Gate A: operator-controlled real Hyper-V lifecycle preflight

**State: BLOCKED (no real-host execution recorded).** This is for a dedicated, operator-approved Windows validation host and the existing fixed protocol-test guest only. The tests create and destroy VMs and differencing disks; they do not execute a coding task, transfer a repository, or validate the future tool protocol. Do not enable Hyper-V, elevate, build/download an image, reconfigure networking, or run these tests without explicit approval. See [lifecycle documentation](night_shift_hyperv.md) and [status](night_shift_status.md).

## Before opting in

1. Confirm an approved, dedicated Windows host has Hyper-V and management PowerShell commands, sufficient free space, and an operator account restricted to the test resources as far as host policy permits. `preflight.ps1` checks commands exist; it does **not** attest hardware configuration, permissions, pipe ACLs, or isolation. Ensure no second runner is active. Review the generated sandbox IDs and VM names from the per-test records before any manual cleanup, and approve the test-only workspace root in advance; never run unscoped `reconcile()` alongside another runner.
2. Obtain the reviewed generation-2 Linux protocol-test VHDX outside the repository. Record image provenance/build process, image path and SHA-256, guest OS/service identity, and whether bootstrap and unit match `night_shifts/guest/protocol_test_bootstrap.py` and `night-shift-protocol-test.service`. Inspect that the image has no credentials, host shares or unapproved accounts/services; service/serial files are root-owned and not writable by the worker; `serial-getty@ttyS0` and serial console are disabled. No image path or digest should be selected by task text. Do not substitute the coding-worker image without review.
3. Require `NIGHT_SHIFT_HYPERV_WORKSPACE` to be an operator-designated, initially empty test-only directory outside the checkout. Identify per-test VM/disk ownership markers and ensure backup/retention policy does not turn the differencing disk into a secret leak. Use a reviewed base image whose virtual size is at most the selected disk size. Ensure adequate physical disk space; virtual disk size is **not** a verified physical disk quota.
4. Networking stays **off**: `host_config.switch_name` is `None`, `sandbox_spec.network_enabled` is `False`, and `create.ps1` omits `SwitchName`. On the real host, verify test VMs have no switch attachment or guest network connectivity and no host mounts; an unconnected virtual adapter may still exist. Confirm the VM's COM1 named pipe `\\.\pipe\night-shift-<sandbox-id>-com1` is only accessible to the intended host principal; validate ACL/creator identity and guest isolation from other host services before trusting any tool-session data. Current tests do not automatically check pipe ACLs or assert network-adapter state.
5. Set bounded timeouts/resource choices and decide whether the guest image's `RuntimeMaxSec=6h`, `SuccessAction=poweroff`, `FailureAction=poweroff`, and stop-on-disconnect behavior are actually observed. No guest network or arbitrary repository content is needed for the fixed protocol tests. Review service hardening, Hyper-V secure boot template, and serial access on the actual image/host.

## Configured resources versus enforcement evidence

| Setting | Code path / intended enforcement | Missing evidence before broader trust |
| --- | --- | --- |
| `NIGHT_SHIFT_HYPERV_CPU_COUNT` (default 2) | `SandboxSpec.cpu_count` -> `Set-VMProcessor -Count` in `create.ps1` | Inspect actual VM processor config on the approved host. No guest CPU-time quota is set. |
| `NIGHT_SHIFT_HYPERV_MEMORY_MB` (default 2048 in real-host tests; model default 4096) | `New-VM -MemoryStartupBytes`, then `Set-VM -DynamicMemory:$false` | Inspect effective memory; no separate guest cgroup cap is established by this setting. |
| `NIGHT_SHIFT_HYPERV_DISK_GB` (default 20) | `Get-VHD` rejects an oversized parent; `New-VHD -Differencing` and `Resize-VHD` to virtual size when needed | Check virtual size and disk removal on host; no quota for host free space or all guest writable storage. |
| `network_enabled=False` | No switch passed to `New-VM` | Inspect actual VM adapter/switch state and guest routes; no blanket proof of host isolation from the COM1 pipe. |
| Image digest | Host `hashlib.file_digest` at prerequisite/create time and PowerShell `Get-FileHash` during creation | Record image provenance/digest and verify it was the reviewed file; do not infer content safety from SHA-256 alone. |
| `NIGHT_SHIFT_HYPERV_COMMAND_TIMEOUT_SECONDS` (default 180) | Host PowerShell subprocess timeout per script | Does not bound whole cleanup or guarantee a hung guest/reader is stopped. |
| `NIGHT_SHIFT_HYPERV_SERIAL_TIMEOUT_SECONDS` (default 90) | Named-pipe **connect** timeout | Blocking reads after connect have no independent read deadline; stalled stream must be checked in real smoke. |
| `NIGHT_SHIFT_HYPERV_JOB_TIMEOUT_SECONDS` (default 180); `NIGHT_SHIFT_HYPERV_TIMEOUT_TEST_SECONDS` (default 90) | Backend monotonic polling deadline during event streaming | Synchronous create/start/send/retrieve and cleanup have separate bounds; tests must not claim a hard end-to-end runtime cap. |
| Guest lifetime 6h | Provided systemd unit's `RuntimeMaxSec=6h` | Review deployed unit/boot behavior; not a host-enforced lifetime for a compromised guest. |

## Approved run and observation record

After explicit operator approval, configure the variables shown in [the opt-in test instructions](night_shift_hyperv.md#opt-in-real-host-tests), verify the base-image digest independently, and run only `python -m pytest -q tests/night_shifts/test_hyperv_real_host.py` on the dedicated host. The suite creates fresh per-test SQLite stores and exercises prerequisite check; success and rejected-objective round trips; cancellation and timeout during sleep; forced stop/disconnect during sleep; and exact-ID orphan reconciliation. Cleanup uses only this test's store/IDs. The disconnect case deliberately stops its **own** generated VM after seeing the guest sleep event; it does not simulate malformed frames or prove pipe ACLs. Do not run the real-host file with `NIGHT_SHIFT_HYPERV_INTEGRATION=1` during ordinary test runs.

For each run, record: operator approval; sanitized command and variable **names** (never credentials); host/Hyper-V and reviewed image provenance/path/digest; CPU/memory/virtual disk/network/timeouts; cases and pass/fail/skips with elapsed times; observed VM generation, CPU/memory/virtual size, network state and pipe permissions; guest service state; VM name/marker, final host `Get-VM` absence and `worker.vhdx` absence for **each** sandbox; and any unknown/failed cleanup. Do not paste unbounded guest output or secret paths into public reports. If failures leave owned resources, stop accepting jobs, identify exact recorded sandbox IDs and ownership markers and request operator-led cleanup; never sweep other VMs.

**Gate A passes only with recorded real-host observations and confirmed cleanup, not with fake-runner or local protocol tests.** Missing approved host/image/permissions is an explicit blocker. Gate B (real workspace transfer) remains separate.
