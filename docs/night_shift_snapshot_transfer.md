# Commit 04: bounded fixture snapshot and result transfer (offline)

**Not an enabled real-VM data path.** The opt-in Hyper-V lifecycle image still runs the older Phase 3 whole-task bootstrap. The new fixture responder has no installed service or reviewed image; there is no timeout-safe named-pipe `ToolSessionTransport` adapter yet. Do not run `run_fixture_in_sandbox` on a host until the guest image, pipe binding/ACLs, operation deadlines and network-off behavior have been reviewed and separately authorized. Gate A and Gate B remain **BLOCKED**.

`GitSnapshotExporter` reads raw Git objects at an exact full commit OID from an administrator-registered local repository. It never invokes clone, checkout, archive extraction, hooks, smudge/clean filters or repository helpers and never reads the current checkout content for export. The operator must approve a **complete** path-to-SHA-256 map for the commit: an extra tracked file, a missing file or a changed blob is an error. This is a fixture-scale, per-file content approval, **not** an automatic secret scanner. Do not authorize a tracked secret by assuming Git tracking makes it safe. Git output is bounded and has a timeout; lazy fetching and replace objects are disabled. Approved Git repositories and the local Git executable remain trusted host configuration; review object stores/alternates, Git version, local configuration and their provenance before enabling this with untrusted source repositories.

Wire content is canonical JSON with base64 UTF-8 regular files, executable bits (100644/100755), job/repository/full revision and reviewed image digest. The transfer is at most 4 MiB per direction with 16 KiB chunks, 64 files, 256 KiB per file and 2 MiB decoded content; the tracked Git listing is at most 64 KiB. Refuse symlinks, submodules, LFS pointers, binary/NUL/invalid UTF-8, malformed/nonportable paths, duplicate or case-colliding paths, oversized entries and unsafe encodings. No silent omission. Snapshot SHA-256 is recorded in the guest report. Unsupported content blocks the job until an operator chooses another approved fixture/policy; do not substitute a lossy snapshot.

The restricted fixture guest responder only accepts bound `hello`, sequential `load_chunk`, `finalize`, then sequential `export_chunk`; it rejects model tools. A final load validates the complete snapshot before installing files through Linux `openat`/`O_NOFOLLOW` beneath a fresh directory in a **root-owned, non-worker-writable** parent (enforced at installation). This fixed fixture installer needs root privileges; a future coding-worker subprocess must be unprivileged with separately reviewed writable paths. The fixed guest operation compares `fixture.txt` to `night-shift-fixture\n`, writes `fixture-result.txt` exclusively inside that guest workspace and exports a bounded report; it is **not** a repository test or a coding worker. Guest claims are untrusted data: the host validates shape, binding and hash, not semantic correctness in a compromised VM. Never mount or share the host checkout. `run_fixture_in_sandbox` attempts destruction of its exact created sandbox even if transfer/retrieval fails and reports cleanup failure separately; if `create()` fails before returning an ID, operator-side ownership reconciliation is required.

The fixture runner requires trusted `reviewed_image_sha256` and a network-off `SandboxSpec` before creation; an echoed guest image digest is not image attestation. Offline fixture tests use a generated, test-owned Git repository and an in-memory fake serial connection. On non-Linux/non-root test hosts the Linux-only root-owned `openat` installation success test is skipped, rather than claimed as passed. They do not establish a real named-pipe timeout, pipe ACL, VM isolation, process-tree cleanup or guest-service ownership. The existing `ArtifactCollector` and artifact contracts remain in place; the fixed report is not a durable review bundle (Commit 08). Real Gate B requires a reviewed tool-protocol Linux image, audited interruptible transport, opt-in boot/load/fixed-check/retrieve/destroy and failed-retrieval cleanup with VM/differencing-disk absence recorded. Do not treat a mock as gate evidence, enable live model work or run a VM without explicit approval.
